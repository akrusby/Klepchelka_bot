# Klepchelka_bot

Telegram-бот на TypeScript и Node.js. Он принимает текстовые сообщения, при наличии URL загружает содержимое страницы, отправляет запрос одному из настроенных AI-провайдеров и сохраняет переписку в SQLite.

## Возможности

- Работа с Telegram через библиотеку [grammY](https://grammy.dev/) в режиме long polling.
- Ограничение доступа по списку Telegram chat ID.
- Генерация ответов через несколько AI-провайдеров с последовательным переходом к следующему, если текущий завершился ошибкой.
- Загрузка текста веб-страниц, ссылки на которые отправлены в сообщении.
- Хранение сообщений в локальной базе SQLite с отдельной историей для каждого чата.
- Ежедневная публикация списка домашних дел по недельной ротации.
- Личные задачи участников группы с привязкой к Telegram user ID.
- Напоминания, которые сохраняются в SQLite и отправляются в Telegram в назначенное время.
- Команды `/start`, `/memory` и `/diagnostics`.

`dist/`, `node_modules/`, `.env` и файлы `*.db` исключены из Git. База создается относительно текущей рабочей директории процесса, поэтому при запуске из другой директории SQLite-файл будет создан там же.

## Как устроена обработка сообщений

1. При старте приложение читает настройки из переменных окружения, проверяет наличие `BOT_TOKEN` и хотя бы одного разрешенного chat ID, затем запускает grammY long polling.
2. Middleware пропускает сообщения только от ID из `ALLOWED_CHAT_IDS` (или устаревшей одиночной переменной `ALLOWED_CHAT_ID`). Остальным бот отвечает «доступ запрещён».
3. В группах приложение обрабатывает только текстовые сообщения, содержащие одно из отдельных слов «бот», «елебот», «еле-елебот», «балабот», «ботан» (без учета регистра) или точное упоминание `@Klepchelka_bot`. Остальные сообщения игнорируются до обработки задач, сохранения в историю и отправки AI-провайдерам. Telegram доставляет сообщения группы приложению, поскольку Privacy Mode выключен; фильтр действует уже на стороне приложения.
4. Команда `/start` отправляет приветствие, если в сообщении есть триггер «бот» или упоминание бота. `/memory` показывает до 20 последних сообщений текущего чата. `/diagnostics` показывает uptime, версию Node.js, использование памяти, счетчик сообщений и состояние последнего AI-запроса. В группе добавляйте «бот» к командам, например `/myid бот`.
5. Напоминания и сообщения о личных задачах сначала обрабатываются серверной логикой. Напоминания сохраняются в SQLite; AI используется только для сопоставления сообщения о выполнении с личными невыполненными задачами. Остальные подходящие текстовые сообщения проходят стандартную AI-обработку.
6. AI prompt содержит системные инструкции, до 8 000 символов истории, до 4 000 символов нового текста и до 12 000 символов текста страницы. Провайдеры пробуются в порядке из `AI_PROVIDER_ORDER`; по умолчанию — `groq,gemini,openrouter,cloudflare,openai,anthropic`. У OpenRouter три последовательных варианта модели. Если все попытки завершаются ошибкой, бот сообщает, что AI-провайдеры недоступны.
7. Успешный ответ сохраняется в SQLite и отправляется пользователю.

Загрузчик URL принимает только `http` и `https`, не следует HTTP-редиректам, ограничивает обычный ответ размером 1 MB и блокирует некоторые localhost/private IPv4-адреса. Для ссылок `chatgpt.com/share/...`, которые не удалось загрузить обычным HTTP-запросом, предусмотрен fallback на Chromium через Playwright. Эта проверка не является полноценным сетевым firewall для исходящих запросов.

В таблице `messages` хранятся `chat_id`, роль (`user` или `assistant`), текст и время создания. Таблицы `household_assignments`, `household_schedule_state` и `household_daily_notifications` хранят план ротации, начало текущего цикла и информацию об уже отправленных списках. `daily_tasks` остается в SQLite для совместимости с прежними данными. В `personal_tasks` задачи разделены по чату и Telegram user ID и содержат дату, описание и статус выполнения. В `reminders` хранятся напоминания, время отправки и отметка о доставке. История сообщений автоматически не удаляется. Команда `/memory` и prompt используют последние 20 сообщений, но общий объем базы со временем растет.

## Требования

- Node.js, совместимый с установленными версиями зависимостей проекта (для сервера рекомендуется поддерживаемая LTS-версия).
- npm.
- Telegram bot token и как минимум один AI API key.
- Для browser fallback загрузчика ChatGPT shared pages — браузер Chromium, устанавливаемый через Playwright.

## Настройка

Создайте `.env` в корне проекта. Не добавляйте этот файл, токены или API-ключи в Git.

Обязательные параметры:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен Telegram-бота |
| `ALLOWED_CHAT_IDS` | Разрешенные chat ID через запятую; рекомендуется использовать эту переменную |
| `DAILY_TASK_CHAT_ID` | Chat ID разрешенной группы, куда ежедневно публикуется список домашних дел в 09:00; если не задано, ротация выключена |

Вместо `ALLOWED_CHAT_IDS` код также принимает `ALLOWED_CHAT_ID` с одним ID.

AI-провайдеры (достаточно настроить один или несколько):

| Переменная | Провайдер |
| --- | --- |
| `GROQ_API_KEY` | Groq |
| `GEMINI_API_KEY` | Google Gemini |
| `OPENROUTER_API_KEY` | OpenRouter |
| `OPENAI_API_KEY` | OpenAI |
| `ANTHROPIC_API_KEY` | Anthropic |
| `CLOUDFLARE_API_TOKEN` + `CLOUDFLARE_ACCOUNT_ID` | Cloudflare Workers AI (оба параметра обязательны вместе) |

Опциональные параметры:

| Переменная | Назначение |
| --- | --- |
| `AI_PROVIDER_ORDER` | Порядок групп провайдеров через запятую. Значения: `groq`, `gemini`, `openrouter`, `cloudflare`, `openai`, `anthropic`; по умолчанию бесплатные варианты идут до платных |
| `GROQ_MODEL` | Модель Groq; по умолчанию `openai/gpt-oss-120b` |
| `GEMINI_MODEL` | Модель Gemini; по умолчанию `gemini-3.6-flash` |
| `OPENROUTER_MODEL` | Модель OpenRouter; по умолчанию `google/gemma-4-26b-a4b-it:free` |
| `OPENROUTER_DOTS_MODEL` | Вариант Dots в OpenRouter; по умолчанию `dots-studio/dots-3-note-preview:free` |
| `OPENROUTER_LING_MODEL` | Вариант Ling в OpenRouter; по умолчанию `inclusionai/ling-3.0-flash-sante:free` |
| `OPENAI_MODEL` | Модель OpenAI; по умолчанию `gpt-4o-mini` |
| `ANTHROPIC_MODEL` | Модель Anthropic; по умолчанию `claude-haiku-5-5` |
| `CLOUDFLARE_MODEL` | Модель Workers AI; по умолчанию `@cf/qwen/qwen3-30b-a3b-fp8` |
| `BROWSER_HEADLESS` | Если установить в `false`, Playwright запустит браузер не в headless-режиме; по умолчанию headless |

Пример `.env` с фиктивными значениями:

```dotenv
BOT_TOKEN=replace-with-telegram-token
ALLOWED_CHAT_IDS=123456789,987654321
GROQ_API_KEY=replace-with-groq-key
GEMINI_API_KEY=replace-with-gemini-key
OPENROUTER_API_KEY=replace-with-openrouter-key
AI_PROVIDER_ORDER=groq,gemini,openrouter,cloudflare,openai,anthropic
```

Не задавайте API-ключи, которыми не располагаете: незаданные провайдеры не будут включены.

OpenRouter последовательно пробует основную модель, бесплатную Dots3-Note Preview и бесплатную Ling 3.0 Flash Sante. У бесплатных моделей OpenRouter общий лимит аккаунта/провайдера (на дату проверки — 20 запросов в минуту и 50 в день для аккаунтов без купленных кредитов); наличие `:free` в каталоге не гарантирует постоянную доступность или отсутствие 429. Ling Sante — модель специализированной медицинской тематики, поэтому оставлена последним вариантом OpenRouter, а не основным семейным ассистентом. Подробности — в [правилах бесплатных моделей](https://openrouter.ai/docs/guides/routing/model-variants/free) и [лимитах API](https://openrouter.ai/docs/api_reference/limits).
При ручном переопределении `OPENROUTER_MODEL`, `OPENROUTER_DOTS_MODEL` или `OPENROUTER_LING_MODEL` убедитесь, что выбранная модель действительно имеет бесплатный вариант; иначе запросы могут тарифицироваться.

Cloudflare Workers AI включается только при наличии обоих параметров `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Текущая документация описывает бесплатную квоту 10 000 Neurons в день; исчерпание квоты на Free plan приводит к отказу, а не к автоматическому платному продолжению. По умолчанию используется [Qwen3 30B A3B](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/), который совместим с Chat Completions API через [OpenAI-совместимую точку входа](https://developers.cloudflare.com/workers-ai/configuration/open-ai-compatibility/). У отдельных моделей, включая GLM-5.3-Flash, требуется оплачиваемый план/способ оплаты. См. [тарифы и дневную квоту](https://developers.cloudflare.com/workers-ai/platform/pricing/).

GLM-5.3-Flash через OpenRouter в каталоге на 8 октября 2026 г. не имеет бесплатной `:free` версии, поэтому он не включен в бесплатные fallback-модели. Платные OpenAI и Anthropic остаются в цепочке после бесплатных провайдеров, но начнут успешно отвечать и тарифицироваться, если на их аккаунтах появится баланс/кредиты.

## Ротация домашних дел

Если задан `DAILY_TASK_CHAT_ID`, бот ежедневно публикует в семейной группе назначения на текущий день в 09:00 по часовому поясу `Europe/Warsaw`. В одном сообщении перечислены Андрей, Настя, Катя и Лиза; участник без назначений отмечен как отдыхающий. Список не отправляется в личные чаты и сам по себе не создает личные задачи в `personal_tasks`.

План создается на скользящие семидневные циклы при первой отправке. В каждом цикле: пылесосить квартиру — 1 раз, кухню — 3 раза, детскую — 1 раз, мыть унитаз, ванную и зеркала и протирать пыль — по 1 разу. Одно и то же дело не назначается одному человеку два раза подряд, включая границу между циклами; детскую могут убирать только Катя и Лиза. Назначения случайны и по возможности балансируются по нагрузке. Уборка кухни распределяется по разным дням с промежутком не менее одного дня; ежедневно назначается одно или два дела.

Для восстановления после перезапуска план и отметка об отправке каждого дневного списка хранятся в SQLite. Scheduler проверяет время по `Europe/Warsaw`; при старте службы отправка возможна в течение пяти минут после 09:00. Если служба недоступна в это окно, список за день пропускается. Отметки выполнения домашних дел бот не обрабатывает.

## Напоминания

В групповом чате попросите бота напомнить о событии с указанием «сейчас» или относительного времени: например, «Бот, напомни @Acruxby через час, чтобы закинул 8 злотых за еду в школе» или «Бот, напомни сейчас позвонить маме». Поддерживаются секунды, минуты, часы и дни (числом или словами от одного до десяти), максимум — один год. Текст вместе с упоминанием сохраняется в SQLite, а `@username` отправляется как Telegram-упоминание в исходный чат, поэтому напоминания переживают перезапуск процесса. Если в коротком продолжении вроде «напомни сейчас» текст не указан, бот переносит последнее ожидающее напоминание этого автора на новое время. Бот проверяет очередь каждые 15 секунд и отправляет накопившиеся просроченные напоминания после запуска; при ошибке Telegram оставляет напоминание в очереди для повторной попытки.

## Личные задачи участников

Задачи относятся к паре «группа + Telegram user ID»: каждый участник видит и меняет только собственные задачи. Команда `/myid` показывает ID автора, а обработчик не доверяет имени/тексту пользователя для определения владельца.

В групповом чате начинайте обращение со слова «Бот», «Елебот», «Еле-елебот», «Балабот» или «Ботан» либо включайте любое из этих отдельных слов в сообщение. Также срабатывает точное упоминание `@Klepchelka_bot`. Регистр не важен. Обычная семейная переписка без такого триггера игнорируется и не сохраняется в историю. Например:

- «Бот, какие у меня задачи на сегодня?» — список невыполненных задач на сегодня.
- «Бот, какие у меня задачи на завтра?» — список на завтра.
- «Бот, добавь мне на сегодня купить молоко» — добавление задачи на сегодня.
- «Бот, добавь на завтра позвонить врачу» — добавление задачи на завтра.
- «Бот, я купил молоко» — AI сопоставляет сообщение только с невыполненными задачами автора на сегодня. Изменение выполняется, только если модель вернула ID одной из предложенных задач и уверенность не ниже 0.8; иначе бот просит уточнение или оставляет список без изменений.
- «@Klepchelka_bot кто последний фараон Египта?» — обычный вопрос, он передается AI-провайдерам в настроенном порядке; бот отвечает результатом первого успешного провайдера. Это не отдельные автономные агенты, а подключенные модели через API.

Privacy Mode выключен через BotFather, чтобы Telegram доставлял приложению все сообщения семейной группы. Код приложения фильтрует групповой текст до сохранения/обработки: AI и логика задач запускаются только для сообщений с отдельным словом «бот» либо `@Klepchelka_bot`. Поэтому обычная переписка не попадает в историю бота и не отправляется AI, хотя технически приходит на VM.

Домашний список публикуется в семейной группе и распределяется по отображаемым именам. Telegram ID участников не нужны для этого группового сообщения.

## Запуск и сборка

Установите зависимости:

```bash
npm ci
```

Для локальной разработки с запуском TypeScript напрямую:

```bash
npm run dev
```

Для сборки и запуска скомпилированной версии:

```bash
npm run build
npm start
```

Скрипт `build` компилирует `src/` в `dist/`; `start` запускает `dist/index.js`. Отдельных тестовых или lint-скриптов в `package.json` сейчас нет.

Для поддержки browser fallback на Linux после установки зависимостей Playwright установите Chromium и необходимые системные библиотеки. Вариант команды Playwright:

```bash
npx playwright install --with-deps chromium
```

Эта команда может требовать прав администратора для установки системных библиотек. Если fallback не нужен, браузер можно не устанавливать.

### Сетевая схема

Бот использует long polling: он сам устанавливает исходящие соединения к Telegram и AI API. Входящий HTTP/HTTPS endpoint для Telegram webhook приложению не требуется; reverse proxy и публичный web-порт для самого бота не нужны. VM должна иметь исходящий доступ к Telegram и выбранным AI-провайдерам. По предоставленным сведениям, для администрирования VM используется Native SSH по TCP-порту 22, доступный с исходного IP клиентской машины согласно примененным NSG rules. Не расширяйте правило SSH на все IP без необходимости; при смене сети проверьте разрешенный source IP в Azure NSG.

### Шаблон развертывания на Linux с systemd

Приложение уже работает как systemd-служба на этой VM. Следующие инструкции — шаблон для повторного развертывания, а не просьба подключаться к VM для текущей диагностики. Значения ниже показаны для текущей конфигурации там, где они проверены; команды следует выполнять только при необходимости развертывания/обслуживания. Проверяйте дату последнего обновления приложения отдельно: наличие локальных изменений в Git не означает, что они уже развернуты на VM.

1. Создайте отдельного системного пользователя и каталог приложения. Установите поддерживаемые Node.js и npm.
2. Получите код проекта в `/home/azureuser/klepchelka-bot` и установите зависимости. В текущей VM этот каталог не является Git-клоном, поэтому обновление выполняется передачей проверенных build-артефактов через Azure VM Run Command, а не `git pull`:

   ```bash
   cd /home/azureuser/klepchelka-bot
   npm ci
   npm run build
   ```

3. Если необходим browser fallback, установите Chromium Playwright и требуемые системные библиотеки.
4. Секреты находятся в `/home/azureuser/klepchelka-bot/.env`. Не перезаписывайте этот файл при развертывании; ограничьте доступ к нему, например:

   ```bash
   chmod 600 /home/azureuser/klepchelka-bot/.env
   ```

   Перед изменением владельца убедитесь, от какого пользователя запускается служба.
5. Для новой установки создайте unit-файл `/etc/systemd/system/klepchelka-bot.service`, проверив пользователя службы и пути. Текущая служба запускает приложение через `xvfb-run`:

   ```ini
   [Unit]
   Description=Klepchelka Telegram bot
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=simple
   User=azureuser
   WorkingDirectory=/home/azureuser/klepchelka-bot
   EnvironmentFile=/home/azureuser/klepchelka-bot/.env
   ExecStart=/usr/bin/xvfb-run -a /usr/bin/node /home/azureuser/klepchelka-bot/dist/index.js
   Restart=on-failure
   RestartSec=5

   [Install]
   WantedBy=multi-user.target
   ```

   Убедитесь, что пользователь службы может читать собранные файлы и `.env`, а также записывать SQLite-базу в рабочую директорию. Этот пример описывает предполагаемую unit-конфигурацию; фактические `ExecStart` и пользователя службы проверяйте в systemd перед изменениями.
6. Включите службу и проверьте запуск:

   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now klepchelka-bot
   sudo systemctl status klepchelka-bot
   sudo journalctl -u klepchelka-bot -f
   ```

База `klepchelka.db` создается в рабочей директории процесса. На VM настроен таймер `klepchelka-backup.timer`, запускающий `klepchelka-backup.service`; проверяйте расписание через `systemctl list-timers klepchelka-backup.timer` и результат каждого запуска через `journalctl -u klepchelka-backup.service`. Сам факт наличия таймера не гарантирует успешную резервную копию. Для согласованной копии работающей SQLite-базы используйте SQLite backup API/утилиты или остановите службу на время копирования; не удаляйте файлы `-wal`/`-shm` вручную у работающей базы.

## Диагностика и обслуживание

- `sudo systemctl status klepchelka-bot` — состояние службы в приведенном systemd-примере.
- `sudo journalctl -u klepchelka-bot -f` — поток логов службы.
- `/diagnostics` — runtime-диагностика бота и последнего AI-запроса в Telegram.
- `/memory` — последние сохраненные сообщения конкретного чата.
- Следите за работой `klepchelka-backup.timer` и свободным местом; таблица сообщений не очищается автоматически.
- Не публикуйте журналы без проверки: в них могут присутствовать тексты сообщений, URL и ошибки внешних API.
- Ротация и срок хранения журналов зависят от настройки ОС/systemd и в репозитории не конфигурируются.
